Design Rationale
What Pre-Registration Changes
Four key shifts in the user experience when upstream data is available.
✔
Identity Confirmation vs. Data Entry
Pre-filled fields shift the interaction from typing to confirming. Users scan and verify rather than recall and type — reducing cognitive load and error rates. Trust is built by showing where each data point came from.
✕
Coverage Elimination
The entire 3-step coverage flow (Search → Verification → Insurance) is removed. Employer sponsorship and eligibility are verified server-side before the user even starts, turning three friction-heavy steps into zero user-facing steps.
⊟
Address Pre-fill
Shipping address is pulled from employer records, reducing manual entry to a single optional field (apt/suite). The address is shown for confirmation rather than input — saving time and reducing shipping errors.
⚐
Transparency & Trust
Every pre-filled field displays its source (e.g., "From employer") inline. Users understand where the data came from, feel in control, and can correct inaccuracies — preventing silent errors while maintaining a fast experience.
