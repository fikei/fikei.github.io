How I Work

I use a design system as the shared language between me and AI tools. The system defines the rules. The AI writes code that follows them. I review and ship.

Framing

One person, five products, daily shipping. The challenge isn't design skill — it's maintaining consistency at speed without a team. The answer: make the design system do the enforcement so I can focus on decisions.

Stack

CTRL DESIGN SYSTEM

CSS files that define colors, type, spacing, components, and AI widget templates. 48 tokens, 24 components, 11 widget types.

SYSTEMIC

A tool I built that crawls websites, extracts their design tokens, and checks them against the design system rules. Flags violations automatically.

CLAUDE CODE

AI that writes code. I give it a feature spec and the design system. It generates components that follow the system's rules. I review and ship.

Design System

The system isn't a Figma library. It's four CSS files. Change the code, run a script, and every product picks up the update. No syncing, no handoff document.

tokens.css → colors, type, spacing components.css → buttons, inputs, cards widgets.css → AI-generated content templates display.css → marketing and portfolio pages ↓ manifest.json → auto-generated index ↓ Systemic → automated QA checks

Four layers. All use the same tokens. All follow the same naming rules. display.css — the one rendering this page — is the newest addition.

11 widget templates. AI generates content that fits into defined layouts (lists, comparisons, stats, checklists, etc.). The AI picks the format; the system controls the look.

When I say "use --accent-cyan on the focus ring," the AI looks up the same token I defined. The design system is a shared vocabulary between me and the machine. It doesn't get stale because it's the live code — not a document about the code.
