# Sassy — Changelog

> Release history for Sassy, the ctrl.rodeo design system

---

## [1.3.0] - 2026-07-30

### Added
- **Sidebar CTAs (`drawer-cta`)** — a hierarchical CTA pattern for sidebars and drawer footers: one filled commit, a quiet dismiss beside it, destructive/state-changing exits as full-width rows below a rule, plus an optional outlined `__alt` for a second forward path. Documented in README and as a story in the recruiting system.

### Changed
- **The design system is named Sassy.** The umbrella name covers the global CTRL layer and every product system under it. Hub, page titles, and stylesheet headers updated; `CTRL` now names the global layer only.

---

## [1.2.0] - 2026-02-09

### Added
- **Runtime design constraint engine** — `boards/design-constraints.js` loads manifest + template registry at runtime, validates widgets against design system rules, annotates DOM with `data-ds-*` attributes, tracks violations
- **Preferred variant marking** — Templates can designate preferred size variants via the variant audit system

### Changed
- **Systemic self-scan** — Systemic can now load the local design system directly via manifest.json + template-registry.json (no crawl needed)
- **All 15 grid sizes exposed** — Template variant gallery shows every size permutation (not just validSizes)

---

## [1.1.0] - 2026-02-07

### Added
- **Widget system** (`widgets.css`) — Grid-based AI widget framework with `w-*` prefix classes: 15 shell sizes, 10 body templates, 12 atoms, 8 molecules
- **Template registry** (`template-registry.json`) — Declarative widget template definitions with valid sizes, required atoms, Boards mappings, fixtures, and edge cases
- **Design system manifest** (`manifest.json`) — Auto-generated index of all tokens, components, and widget classes. Generated by `node scripts/parse-design-system.js`
- **Config-driven AI prompts** — Server-side `config/design-system.ts` embeds template constraints and class allowlist into AI prompts
- **Server-side class validation** — `validateWidgetHtml()` / `sanitizeWidgetHtml()` strip unknown `w-*` classes from AI output
- **Widget feature flag** — Widgets hidden by default; enable via `window.enableWidgetDS()` in browser console
- **Edge-case fixtures** — All 10 templates have `edgeCases` arrays for QA testing
- **Source-of-truth documentation** — Added hierarchy: CSS files (authoritative) > manifest (derived) > registry (reference)

### Removed
- **733 lines dead CSS** — Removed all legacy `widget-outfit__*`, `widget-style__*`, `widget-complete__*` class definitions from Boards

## [1.0.0] - 2026-02-04

### Components Added
- **Buttons**: default, filled, danger, ghost, sm, lg, block variants
- **Form Elements**: input, textarea, select, checkbox, toggle, range
- **Layout**: card, modal, overlay, grid (2-5 columns)
- **Navigation**: tabs, filter-bar, user-menu, dropdown
- **Feedback**: toast, spinner, progress, status-indicator
- **Data Display**: token/tag, account-section

### Tokens Added
- **Colors**: 10-step gray scale, semantic colors (success, error, warning)
- **Typography**: 3 font families, 5 size scales
- **Spacing**: 16-step scale (4px base)
- **Animation**: 3 duration tokens

### Features
- Dark mode as default
- Light mode support (`.light` class)
- Mobile responsive
- High contrast (black/white)
- CORS accessible

## Design Principles

1. **Minimal**: Black/white primary palette
2. **Functional**: Form follows function
3. **Accessible**: High contrast, keyboard nav
4. **Performant**: No JS dependencies
5. **Composable**: Mix and match components
